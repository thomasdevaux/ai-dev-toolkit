# Testing strategy

- Any non-trivial new feature or bugfix needs at least one automated test
  covering its main path before it's considered done — independent of tech.
- No numeric coverage threshold is imposed — too rigid for small tools and
  utilities.
- `docs/testing-strategy.md` is an **on-hold slot** of the doc map: create it
  when there's a deliberate coverage gap worth recording — what's covered,
  what isn't, and why — not before. A suite that simply covers what it should
  needs no document explaining itself.
