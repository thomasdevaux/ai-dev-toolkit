# Full process (not yet designed)

- `process/full` is a placeholder. It is meant for core/critical or
  certified projects that need more rigor than `process/light`, but that
  extra discipline hasn't been designed yet.
- Until it's designed, treat a project synced with `process/full` as if it
  had adopted `process/light`: follow its docs, requirements, ADRs,
  and testing-strategy rules.
- If the project's needs clearly exceed what `process/light` covers (e.g.
  regulatory/certification traceability, formal audit trails), say so
  explicitly to the user rather than inventing ad hoc extra process — that
  gap is what `process/full` will eventually fill.
